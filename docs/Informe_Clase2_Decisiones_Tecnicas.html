1. Decisión de lenguaje de programación

Lenguaje principal: Python

Lenguaje secundario: PHP (Laravel API), TypeScript/JS (dashboard React), Bash

Justificación técnica:
1) Scapy/Nmap/Suricata y tooling de red.
2) Prototipado rápido del scanner/IDS.
3) El tiempo real pesado lo asume Suricata, no Python puro.
4) API Laravel por rapido despliegue y curva de aprendizaje corta.
5) Front con React por rapidez y robustez.

Librerías clave:
Sensores (Python): Scapy, requests/httpx, Pydantic, Nmap, arp-scan.
IDS: Suricata (eve.json) + lector Python.
API: Laravel 13, PHP 8.3+, Sanctum, Reverb, MariaDB.
Dashboard: Vite, React, TypeScript, Cytoscape.
Ops: Bash / Makefile, systemd.

Riesgos identificados:
1. Python no es adecuado para análisis de tráfico a alto pps; el cuello de botella sigue siendo Suricata/config.
2. Stack híbrido (Python + PHP + TypeScript) exige contratos compartidos (contracts/) para no divergir formatos de ingest (ASVS V2.2.1).
3. Capacidades de captura solo en procesos sensor; otorgarlas a la API elevaría privilegios (SSDF PW.1.1).

2. Decisión de agente de IA para el desarrollo

¿Usarán agente de IA?: Sí

Agente elegido: Otro

Justificación:
1. El monorepo Argos se desarrollara usando Cursor: el agente conocera la estructura api/, dashboard/, docs/ y el plan de implementación sin cambiar de herramienta.
2. Permite asistencia multi-stack (Laravel, React/TS y Python) en el mismo flujo de trabajo del equipo.
3. El equipo mantiene control humano: el agente sugiere; arquitectura, citas normativas y alcance legal las validan el líder técnico y el responsable de seguridad.
4. No se eligió Ollama en esta fase porque el hardware/VRAM no es el requisito prioritario frente a velocidad de implementación del MVP; la privacidad se mitiga no pegando secretos (.env, tokens) en el chat.
5. Los agentes que el equipo de desarrollo y analisis usan son: Cursor, Claude Code, ChatGPT

¿Requiere conexión a internet?: Sí

Modelo(s): Modelos del agente se toma automaticamente.

4. Flujo principal de datos

La LAN propia es observada por Scanner (descubrimiento/deep scan) e IDS (Suricata). Ambos sensores envían resultados por HTTP a la API con token de sensor (no escriben en la base de datos). La API Laravel valida (Form Requests + contracts), persiste en MariaDB, emite eventos por Reverb y, si la severidad es high/critical, notifica a Telegram. El dashboard consulta historial por REST (Sanctum) y recibe novedades por WebSocket (Echo/Reverb); en lab, API/Reverb/dashboard se enlazan a 127.0.0.1

5. Observaciones de sustentación

Se sustenta con el plan Argos NetSec Plan de implementación, el informe Clase 1 y el monorepo a desarrollar (api/, dashboard/, docs/, ids/, scanner/). Lenguaje principal Python para sensores; API Laravel y dashboard React como lenguajes secundarios. Agente de desarrollo: Cursor, ChatGPT, Claude Code (Otro). Componentes alineados al alcance Clase 1: sin IPS, sin Docker, bind localhost en lab.
